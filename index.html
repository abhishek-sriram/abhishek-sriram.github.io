How the systems actually work

          MindPulse

          Full-stack AI platform screening young adults for depression and anxiety using PHQ-9 and GAD-7, extended with ML severity prediction, SHAP explainability, a custom Mental Health Index, real-time risk escalation and longitudinal tracking. LLaMA 3.3 70B via Groq generates personalized, symptom-specific guidance.

          • Published paper
          • Repository
          1. PHQ-9 + GAD-7. Questionnaire intake using PHQ-9 and GAD-7 to screen for depression and anxiety. Validated, widely used screening instruments give inputs that clinicians already recognise. Responses are self-reported, so the output is a screening signal, not a diagnosis.
          2. Severity model. ML severity prediction layered on the questionnaire screening. Goes beyond a raw questionnaire score by predicting severity from the full response pattern. Only as reliable as the data it was trained on.
          3. SHAP. SHAP explainability over the severity prediction. A screening result is hard to trust if nobody can see what drove it; SHAP shows which responses pushed the prediction. Adds computation, and it explains the model's behaviour, not the cause of someone's condition.
          4. Mental Health Index. Custom Mental Health Index derived from the screening and severity path. One trackable number makes change over time easy to see. A single score compresses detail, so it should sit beside the symptom-level view.
          5. Risk escalation. Real-time risk escalation when screening signals warrant it. High-risk responses should not wait for a report to be read. The threshold trades missed cases against false alarms.
          6. Longitudinal store. Longitudinal tracking store for screening history over time. Repeated screenings show trends that a single snapshot cannot. Stores sensitive history, so it needs careful access and privacy handling.
          7. LLaMA 3.3 70B. LLaMA 3.3 70B via Groq generating personalized, symptom-specific guidance instead of generic advice. A large open-weight model can write symptom-specific guidance instead of generic advice, and hosted Groq inference keeps responses quick enough for an interactive flow without running GPUs. Relies on a third-party hosted API and sends user text off-platform, and generated guidance is support, not clinical advice.
          8. Guidance. Symptom-specific guidance returned to the user.

          B4iGo conversational agent

          Multimodal LLM-powered conversational chatbot on the B4iGo platform at Infobell IT. Users query their digital footprint and end-of-life preferences in natural language. RAG pipelines perform privacy-preserving retrieval across multiple sensitive data vaults.

          Details generalised for confidentiality.

          1. User query. Natural-language query about the user’s digital footprint and end-of-life preferences.
          2. Multimodal LLM. Lets users ask in natural language about their digital footprint and end-of-life preferences. Plain-language questions are easier than navigating many separate records.
          3. RAG pipeline. RAG pipelines for precise, privacy-preserving retrieval across sensitive vaults. Answers are grounded in the user's own records, not in what the model remembers. Strict privacy boundaries around sensitive data limit how freely one query can combine sources.
          4. Data vaults. Multiple sensitive data vaults queried through privacy-preserving retrieval. Retrieval is designed to be privacy-preserving across multiple sensitive data vaults.
          5. NL answer. Natural-language answer grounded in retrieved vault context.
